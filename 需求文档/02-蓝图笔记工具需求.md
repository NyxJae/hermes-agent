## 一、需求概述

蓝图笔记（Blueprint Notes）是绑定到文件路径或文件夹路径的持久化笔记系统。用于在开发过程中记录文件/文件夹的架构信息、职责范围、依赖关系、注意事项等，供 Agent 在读取文件时自动参考，避免重复询问用户或遗忘关键上下文。

**核心原则：**
- 笔记是**网络节点**——记录框架级、架构级信息，不是日志
- **禁止日志式记录**——杜绝"修改了XX、处理了XX"之类的流水账
- **禁止随意创建 md 文件**——所有工作记录应使用蓝图笔记，除非用户明确要求创建 md 文件
- **Agent 可见、用户可读**——通过数据库持久化，通过查询工具查看

---

## 二、使用规范（写入工具提示词）

### 2.1 MUST NOT — 禁止行为

1. **禁止随意创建 md 文件进行工作汇报**——除非用户明确要求创建 md 文件
2. **禁止日志式记录**——笔记中不得出现"修改了XX、处理了XX、修复了XX"等时间线流水账
3. **禁止记录具体代码实现细节**——代码会变动，笔记应记录"为什么这样设计"而非"代码怎么写"

### 2.2 MUST — 强制行为

1. **所有工作记录使用蓝图笔记工具**——不额外创建文件
2. **每个笔记视为一个网络节点**——包含以下内容：
   - **职责范围**：该文件/文件夹应该做什么、不应该做什么、属于整体架构的哪个部分
   - **大纲**：关键词、关键函数名等便于 grep 搜索的索引
   - **依赖拓扑**：相关文档、相关代码等文件的路径指针（如"参见 `/project/docs/arch.md`"）
   - **注意事项**：边界情况、已知坑点、变更风险

### 2.3 SHOULD — 推荐行为

- 优先使用 `append` 模式追加笔记，而非覆盖
- 定期整理笔记时使用 `overwrite` 模式全量重写，优化结构
- 文件夹笔记记录该目录的整体设计意图，文件笔记记录具体实现约束

## 三、工具设计

### 3.1 工具列表

| 工具 | 参数 | 行为 |
|------|------|------|
| `blueprint_set` | `path`, `content`, `mode`（`append`/`overwrite`，默认 `append`） | 创建或更新笔记。`append` 时自动加时间戳分隔线追加；`overwrite` 时全量覆盖 |
| `blueprint_delete` | `path` | 精确删除指定路径笔记，不级联 |
| `blueprint_query` | `paths` 或 `keywords`（二选一必填，支持 `a\|b\|c` 多查） | 精确匹配查询，返回格式：`/path: 完整内容` |

### 3.2 追加模式分隔格式

每次追加自动加时间戳分隔线：

```
原始内容

--- 2026-04-26 22:45 ---

追加的内容

--- 2026-04-26 23:10 ---

又追加的内容
```

### 3.3 查询返回格式

简洁列表，完整内容不截断：

```
/project/src/utils.py: 职责：工具函数集合。大纲：grep-friendly（web_search, web_extract）。依赖：参见 /project/docs/tools.md。注意：所有工具返回 JSON 字符串。
/project/src/: 职责：核心工具实现。不应包含业务逻辑。
```

## 四、自动触发机制

### 4.1 触发时机

读取文件时（`read_file` 工具调用后），系统自动检查并插入笔记：

- **单工具调用**：工具结果后立即插入笔记 user message
- **批量工具调用**：最后一个工具结果后，统一插入所有笔记 user message

### 4.2 笔记消息格式

```
📎 Blueprint Note [file:/project/src/utils.py]: 职责：工具函数集合。大纲：grep-friendly（web_search, web_extract）。依赖：参见 /project/docs/tools.md。注意：所有工具返回 JSON 字符串。
📎 Blueprint Note [folder:/project/src/]: 职责：核心工具实现。不应包含业务逻辑。
```

### 4.3 递归与去重策略

1. **向上递归**：读取文件时，从该文件路径向上递归到根目录，收集所有文件夹级笔记
2. **会话级去重**：同一会话中，相同路径的笔记只插入一次
3. **早停优化**：遇到会话中已加载过的文件夹级笔记，停止向上递归（该分支已处理）

**举例说明：**

> **场景：读取 `/project/src/utils.py`**
>
> 文件笔记：`/project/src/utils.py` → "职责：工具函数集合..."
> 父文件夹：`/project/src/` → "职责：核心工具实现..."
> 祖父文件夹：`/project/` → "项目根"
>
> **第一次读取：**
> - User: [tool_result: 文件内容]
> - User: `📎 Blueprint Note [file:/project/src/utils.py]: ...`
> - User: `📎 Blueprint Note [folder:/project/src/]: ...`
> - User: `📎 Blueprint Note [folder:/project/]: ...`
>
> **第二次读取 `/project/src/main.py`（同文件夹）：**
> - User: [tool_result: 文件内容]
> - User: `📎 Blueprint Note [file:/project/src/main.py]: ...`（新文件笔记）
> - User: `📎 Blueprint Note [folder:/project/src/]: ...` ❌ 已存在，跳过
> - 向上递归早停：`/project/src/` 已处理，不再检查 `/project/`
>
> **反例（错误行为）：**
> - 错误：每次读取都重复插入相同的文件夹笔记，导致上下文膨胀

## 五、数据存储

### 5.1 数据库选择

- **SQLite**，位于 `~/.hermes/blueprint_notes.db`
- 理由：查询快（关键词搜索、路径前缀匹配），与 Hermes 现有基础设施集成

### 5.2 表结构

```sql
CREATE TABLE blueprint_notes (
    id INTEGER PRIMARY KEY,
    path TEXT NOT NULL,           -- 文件或文件夹绝对路径
    content TEXT NOT NULL,        -- 笔记内容（Markdown 格式）
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

CREATE UNIQUE INDEX idx_notes_path ON blueprint_notes(path);
CREATE INDEX idx_notes_content ON blueprint_notes(content);  -- 全文搜索
```

### 5.3 路径规范

- 统一使用**绝对路径**，避免相对路径歧义
- 文件夹路径以 `/` 结尾（存储时标准化）

## 六、边界情况

| 场景 | 预期行为 |
------|----------|
| `blueprint_set` 路径已存在，`mode=append` | 自动加时间戳分隔线追加 |
| `blueprint_set` 路径已存在，`mode=overwrite` | 全量覆盖，丢失历史追加记录 |
| `blueprint_delete` 路径不存在 | 返回错误："笔记不存在" |
| `blueprint_query` 无匹配 | 返回空列表（非错误） |
| 读取文件时该文件无笔记 | 不插入任何笔记消息 |
| 读取文件时所有父文件夹均无笔记 | 不插入任何笔记消息 |
| 会话级去重表丢失/重置 | 重新插入笔记（幂等，LLM 看到重复笔记但不影响正确性） |
